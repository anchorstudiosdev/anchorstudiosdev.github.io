Attribute-driven inspectors without editor code, and tools for every Inspector window. The tools work as soon as the package is imported: a Navigation Bar with history and bookmarks, a Header Extender under asset titles, a Component Bar on component headers, component shortcuts, searchable enum fields and field search. The attributes go on your own scripts: [SectionedInspector] turns [Header] attributes into nested, foldable sections with badges and tooltips, and conditions, buttons, callbacks, groups and tabs work on any script. Every feature has its own switch.

Quick Start

  1. Select anything. The Inspector gains a Navigation Bar along its top, component headers show buttons when you point at them, assets get a toolbar under their title, and enum fields open a searchable popup.
  2. Mark a MonoBehaviour or ScriptableObject with [SectionedInspector]. Its [Header] attributes become foldable sections.
  3. Add attributes where you need them. Tabs, conditions, buttons and callbacks work on any script. 
using Anchor.Inspector;
using UnityEngine;

[SectionedInspector]
public class Enemy : MonoBehaviour
{
    [Tab("Stats")]
    [Header("Health")]
    [SerializeField] private int maxHealth = 100;

    [SerializeField] private bool regenerates;

    [ShowIf(nameof(regenerates))]
    [Unit("hp/s")]
    [SerializeField] private float regenRate = 2f;

    [Tab("Loot")]
    [SerializeField] private int gold = 5;

    [Button]
    private void ResetStats() => maxHealth = 100;
}

Out of the Box

These work as soon as the package is imported, with no code.

Navigation Bar

A bar at the top of every Inspector window.

  • Back and Forward step through recently selected objects, skipping any that no longer exist.
  • Bookmark chips, as many as fit, with the rest in a searchable … list:
    • Click selects and pings; Ctrl/Cmd-click adds to or removes from the selection.
    • Double-click opens an asset or frames a scene object in the Scene view.
    • Drag a chip onto an object field, the Scene view or the Hierarchy, or along the strip to reorder. Drop objects on the strip to bookmark them.
    • Right-click for a menu; middle-click removes the bookmark.
    • With Anchor Hierarchy installed, Alt/Option-click a scene object's chip to open Hierarchy's palette and set its row color, icon or note.
  • The star bookmarks or removes the object the window shows.
  • A locked Inspector's bar follows its own object.
  • With Anchor Quick Select installed, bookmarks in closed scenes show as dimmed chips: click one to open its scene and select the object, or right-click for a menu that can also open the scene additively.
  • Bookmarks are shared with Anchor Hierarchy and Anchor Quick Select when they are installed. With Anchor Hierarchy on, a chip shows the object's icon as Hierarchy resolves it, including one set in its palette.

Header Extender

A toolbar under an asset's title in the Inspector.

  • Edit opens a script in your IDE (for a ScriptableObject, the script that defines it), a prefab in Prefab Mode, and any other asset in its default editor.
  • Find Refs selects the asset and runs Unity's Find References In Scene.
  • Ping pings it in the Project window.
  • Open In Window opens a new Inspector locked to it.
  • The ⋮ menu: Duplicate, Reveal in Explorer/Finder, Copy GUID, Copy Asset Path, Select Instances In Scene for a prefab, and Recount References.
  • A missing badge counts missing scripts and broken references on prefabs and ScriptableObjects.
  • Used by: click to scan the project for assets referencing this one. Progress shows on the badge, and the results list in the Console.
  • Asset Types picks which kinds of asset get the toolbar. Folders and scene objects never do.

Component Bar

Buttons on every component's header. By default they show while the pointer is over the header.

  • Edit opens the component's script.
  • Copy adds the component to Anchor's clipboard, which collects copies across objects until cleared.
  • Paste pastes a copied component's values onto a component of the same type.
  • Paste N Components, under Add Component, adds every copied component as a new one. A copied Transform is skipped, and so is a second copy of a component that allows only one.
  • Save keeps a scene component's values when Play Mode stops, written back with Undo. Tools > Anchor > Inspector > Play Mode Saved Components lists what is queued.
  • With several objects selected, Paste, Save and Paste N Components act on each of them, one Undo step each.
  • GameObject > Anchor > Copy Components To Selection copies every component of the active object onto the other selected objects.

Shortcuts

Registered with Unity's Shortcut Manager under Anchor > Inspector, so each can be rebound or removed:

ShortcutDoes
Ctrl+Shift+ECollapse or expand every component in the Inspector under the cursor, else the focused one
Shift+ECollapse every component except the one under the cursor
Shift+ATurn the component under the cursor on or off
Shift+XRemove the component under the cursor
  • The last three act on the component under the cursor for every selected object.
  • Shift+X never removes a Transform, or a component another one requires; a notification says why.

Searchable Enums

Enum fields open a searchable popup in place of Unity's.

  • Search by display name, by name in code, or by the number beside each member.
  • Up and Down move through the results while you type; Enter picks.
  • Favorites, per enum type and project: star a member, show only favorites, or pin them to the top.
  • Add Members From Search: a search that matches no member offers + Add. After a confirmation naming the script and line, the member is added to the enum's declaration, the script recompiles, and the field is set to it as one Undo step. Only enums in the project's own editable scripts can be changed, and the script edit itself can't be undone.
  • The field behaves like Unity's own: prefab overrides, the right-click menu, mixed values and Undo.
  • [Flags] enums, and enums with fewer than Minimum Members, keep Unity's own control.

Field Search

  • A search box above the fields of any MonoBehaviour or ScriptableObject with at least Minimum Fields of them (12 by default), unless it has its own custom editor.
  • It matches field names, and on a sectioned type also section paths and badge labels.
  • Groups with a match open while you type, and clearing the box puts them back.
  • It matches top-level fields, not fields inside a list, a struct or a [SerializeReference] value.

With Attributes

Add these to your own MonoBehaviours and ScriptableObjects. They live in the Anchor.Inspector namespace, and no editor script is needed.

Sectioned Inspectors

using Anchor.Inspector;
using UnityEngine;

[SectionedInspector]
public class EnemyConfig : ScriptableObject
{
    [Header("Stats/Health")]
    [SerializeField] private int maxHealth = 100;

    [Header("Stats/Movement")]
    [SerializeField] private float moveSpeed = 3f;

    [Header("Rewards")]
    [SerializeField] private int gold = 5;
}
  • A [Header] path becomes nested sections: Stats/Health and Stats/Movement are two cards inside one Stats card. The separator is / by default.
  • A [Header] applies to its field and every field after it until the next one, as in Unity's own Inspector. When one field carries two, the one nearest the field sets its section.
  • Each section remembers whether it is open, per type.
  • Rows split between label and value by percentage, so they fill the Inspector at any width.
  • Arrays, lists, [SerializeReference] fields and nested classes keep Unity's full-width layout.
  • A type without [SectionedInspector] keeps Unity's own default Inspector.

Badges

Pills beside a field's value, on sectioned types.

[Required]        // REQ       red: must be assigned
[RuntimeValue]    // RUNTIME   amber: written by code at runtime
[Deprecated]      // OLD       gray: kept so older data still loads
[Unit("m")]       // m         blue: the unit of the value
[SerializeField] private float range = 12f;
  • Write your own by subclassing FieldBadgeAttribute: 
public sealed class ExperimentalAttribute : FieldBadgeAttribute
{
    public ExperimentalAttribute() : base("EXP", "Not final. May change.", BadgeTint.Amber) { }
}
  • BadgeTint.Accent, the default, follows the Icon Accent color; Red, Amber, Green, Gray and Blue stay fixed.
  • A field can carry several badges.
  • Other inspector assets define a [Required] too. In a file that imports both namespaces, write [Anchor.Inspector.Required] or add using Required = Anchor.Inspector.RequiredAttribute;.

Tooltips

A field's [Tooltip] always shows on hover. On a sectioned type, Tooltip Display can show it too:

  • Badge (default): a ? pill that expands the text under the row.
  • Below: dim text under the row.
  • Beside: dim text in a column beside the field.
  • Off: hover only.

Groups & Tabs

[Tab("Combat")]
[SerializeField] private int damage = 10;

[Foldout("Critical Hits")]
[SerializeField] private float critChance = 0.1f;
  • [Tab] puts a field, and every field after it until the next one, in a tab. Fields before the first [Tab] go in a General tab, and a type with a single tab shows no strip.
  • [Foldout] puts one field in a named foldout wherever it is declared; other fields with the same name join it.
  • On a sectioned type, [Header] sections nest inside tabs. On any other type the fields Unity built move into foldouts and tab panes, and each [Header] stays where Unity draws it.

Conditions

[ShowIf(nameof(isEnabled))]                                        // while a bool is true
[ShowIf(nameof(mode), Mode.Ranged)]                                // while an enum equals a value
[ShowIf(nameof(tier), Tier.Gold, Tier.Platinum)]                   // while it equals any of them
[HideIf(nameof(isLocked))]                                         // the inverse of ShowIf
[EnableIf(nameof(level), AnchorComparison.GreaterThanOrEqual, 10)] // grays out instead of hiding
[ReadOnly]                                                         // never editable
  • They work with or without [SectionedInspector], in UI Toolkit and IMGUI inspectors.
  • A condition reads a sibling field: a bool, an int, a float (comparisons only), an enum by its value, so a [Flags] enum compares as a bitmask, or an object reference, by whether one is assigned.
  • Comparisons: LessThan, LessThanOrEqual, GreaterThan, GreaterThanOrEqual, EqualTo and NotEqualTo.
  • Conditions update as the sibling changes.
  • On a sectioned row the whole row follows the condition: label, value, tooltip and badges.
  • Several conditions on one field combine: every hiding condition must pass for the field to show, and every disabling one for it to be enabled.
  • On a list or array, a sectioned row applies the condition to the whole field. On any other type Unity runs the condition for each element, so the elements hide or gray out while the list's header and size stay.
  • Conditions fail open. A sibling that can't be read, selected objects whose values differ, or a value that can't be compared all leave the row visible and enabled. A misspelled sibling name also logs one error.
  • Write your own by deriving from AnchorShowIfAttribute, AnchorHideIfAttribute or AnchorEnableIfAttribute and overriding Evaluate. A condition that derives from AnchorConditionAttributeBase or implements IAnchorFieldCondition directly has no property drawer, so it applies on sectioned types only.

Buttons

[Button]
private void RecalculateStats() { ... }

[Button("Reset To Defaults")]
private void ResetDefaults() { ... }
  • A parameterless method becomes a button in an Actions card after the fields.
  • A click records Undo on every selected object and shows what the method changed at once. It also marks their scene or asset modified, so Unity asks to save what the method changed elsewhere.

Reacting to Edits

[OnValueChanged(nameof(RecalculateDerived))]
[SerializeField] private int baseDamage;

private void RecalculateDerived() { ... }
  • Calls a parameterless method on the same object, public or private, whenever the field changes in the Inspector.
  • On a list or array it runs when an element changes, not when one is added or removed.

Names & Assemblies

Every attribute also has an Anchor-prefixed name: [AnchorShowIf], [AnchorHideIf], [AnchorEnableIf], [AnchorReadOnly], [AnchorOnValueChanged], [AnchorButton], [AnchorGroup] for [Foldout], and [AnchorTab]. Use it in a file where another asset's attribute of the same name is also in scope.

The attributes live in the Anchor.Inspector.Attributes assembly, which Unity's own script assemblies reference automatically. A script inside your own assembly definition needs Anchor.Inspector.Attributes added to its Assembly References.

Settings

The Inspector page under Preferences > Anchor, one foldout section per feature. Each section's checkbox turns its feature on or off.

Navigation Bar

  • Back / Forward Buttons, Bookmark Chips and Bookmark Toggle: the parts of the bar.
  • Closed Scene Bookmarks: dimmed chips for bookmarks in closed scenes, offered while Anchor Quick Select is installed.
  • Bar Height (px): the bar's height; its buttons and chips scale with it.

Header Extender

  • Asset Types: prefabs, ScriptableObjects, scripts, materials, textures, models, audio, animation, scenes and other assets.
  • Edit, Find Refs, Ping, Open In Window, Overflow Menu, Missing-Reference Badge and Used-By Badge: show or hide each.

Component Bar

  • Edit Button, Copy Button, Paste Button and Save Button: Always, On Hover or Off.
  • Save Only In Play Mode: hide Save outside Play Mode, where it can only queue a component.
  • Accurate Value Restore (Experimental): also restore references to scene objects when Play Mode stops, and show restored values as prefab overrides.

Sectioned Layout

  • Header Separator: splits a [Header] into nested sections.
  • Label Width %: the label's share of the label and value.
  • Header Accent: the color of main section headings.
  • Sections Expanded By Default: whether a section starts open the first time it is seen.
  • Show Script Field: shows the Script field on sectioned scripts. Off by default, since the Component Bar's Edit button opens the script.
  • Script Field Above Sections: draws a shown Script field as a plain row above the tabs and sections, as Unity does; off puts it in the first section.
  • Tooltip Display, with Tooltip (Beside) Width %.
  • Show Field Badges, with Badge Width %, the badge column's smallest share.
  • Icon Accent: the color of the tooltip pill and of Accent badges.

Field Search

  • Minimum Fields: the fewest fields an inspector needs to show the search box.

Searchable Enums

  • Minimum Members: smaller enums keep Unity's popup.
  • Add Members From Search.
  • Row Numbers: the number beside each member: its Position, its Value, or Off.
  • Popup Background, Zebra Striping with Even Row Color and Odd Row Color.
  • Pin Favorites To Top and Always Show Favorite Icon.
  • Auto-Scroll To Selected, Min Height, Max Height, and Match Dropdown Width or Min Width.

Shortcuts

Lists the shortcuts with their current bindings. The section's checkbox turns all four on or off.

Compatibility

Anchor Inspector registers custom editors for MonoBehaviour and ScriptableObject, so it can section marked types, and a property drawer for enum fields. Both editors are fallbacks, so any other custom editor wins: a type with its own editor keeps it, and an asset that registers an editor for every object keeps drawing them.

  • Where another editor draws a type, Anchor's conditions, callbacks and Searchable Enums still apply to its fields. Sectioning, groups, tabs, the search box and buttons need Anchor's editor; derive one from SectionedInspectorEditor for that type, as described below.
  • Turn the module off on its Preferences page, or any feature in its section. Sectioned types then use Unity's own layout and enum fields Unity's own popup, while conditions, callbacks, buttons, groups and tabs keep working.
  • Define ANCHOR_INSPECTOR_NO_GLOBAL in Player Settings > Scripting Define Symbols to leave all three registrations out, for a project where another asset registers its own. A type can still be sectioned: derive an editor from SectionedInspectorEditor with [CustomEditor(typeof(YourType))], or call AnchorSectionedInspector.Build(serializedObject) from your own editor. An editor inside your own assembly definition needs Anchor.Inspector in its Assembly References.
