Anchor PlayerPrefs

See and edit PlayerPrefs live in Play Mode, with Undo, snapshots to compare and restore, a sandbox for every run, a log of every write, and the code using each key.

View, edit and snapshot the project's PlayerPrefs and Unity's EditorPrefs in one window, live while the game runs in Play Mode. Every edit is one Undo step, snapshots compare and restore whole saves, and the Changes page records every write in order.

Anchor PlayerPrefs reads the prefs where the Editor keeps them on Windows, in the registry. It supports Windows only. On macOS and Linux it compiles, and its window says the platform isn't supported.

Quick Start

  1. Open the window: Tools > Anchor > PlayerPrefs > Open Anchor PlayerPrefs, or Alt+S.
  2. Every key of this project's PlayerPrefs is listed with its type and value. Search, filter by type, or click a column title to sort.
  3. Click a value to edit it, and press Enter. Ctrl+Z takes it back.
  4. Enter Play Mode with Watch on: rows the game changes light up.
  5. Snapshots ▾ > Take Snapshot... saves every key as it is now, to compare with later and restore.

The Key List

  • Search matches keys and values, and readable names while they're on.
  • All Types shows one type only.
  • Show grouped folds keys into groups at their prefix separators: Save_Slot_1 and Save_Slot_2 fold into a Save_Slot group. Click a group's row to open or close it, or use the Left and Right arrow keys. A group holding one key shows the key instead.
  • Readable Names, in Preferences, shows keys the way the Inspector shows field names: player_coins reads Player Coins. The tooltip keeps the raw key.
  • Show hidden shows hidden keys too, dimmed.
  • Drag the line between two column titles to resize the columns; the widths are kept.
  • Refresh reads the store again and says what it found.
  • A JSON value shows in the list as a one-line summary of its members. Editing it in the list shows it in full.
  • The checkboxes follow the list's selection; the one in the header selects every row.

Each row has buttons at its end: copy the key, copy the value, find the key in code, hide it, the row's menu, and delete. The bookmark star sits at its start. The right-click menu also copies the line of C# that reads the key, such as PlayerPrefs.GetInt("Player_Coins"), renames the key and changes its type.

Editing

  • A value: click it, type, press Enter. A value that isn't a valid number for its type is refused.
  • Rename: F2, or Rename in the row's menu. A name another key has asks before replacing it.
  • Change type: click the type. A number converts; text that isn't a number becomes 0, after asking.
  • Add: ＋ Add Key opens the New key panel. Pick the type, type the key and the value, and press Enter; the panel stays open for the next key and keeps its prefix. Add Key Here on a group's menu starts the key with the group's prefix. A key that exists is replaced, and the panel says so first.
  • Delete: the row's button, the Delete key, or Delete Selected. Several keys are confirmed first.
  • Delete All deletes every PlayerPrefs key of the project, Unity's own included. A snapshot named Before Delete All is taken first.

Every edit, rename, type change, delete and restore is one step on Unity's Undo, so Ctrl+Z and Ctrl+Y work as anywhere in the Editor, after a script recompile too. The last 500 steps are kept.

List Edits in Preferences chooses when an edit made in the list is written:

  • Write At Once: as soon as it's made.
  • Hold Until Applied: edited rows are marked, and Apply All in the bar under the list writes them as one Undo step. Revert All drops them.
  • Apply Per Row: each edited row has its own Apply and Revert buttons.

Held edits survive a script recompile, and closing the window asks whether to apply them. A held key the game changes meanwhile turns red.

Details

The pane under the list shows the selected key in full. Details in the toolbar shows or hides it, and its top edge drags to resize it.

  • Edit the key, the type and the value, then Apply, or Enter in the key field. Revert, or Esc, drops the edits.
  • Text shows the value as it is stored. Structured shows JSON as a tree of fields and Unity's semicolon lists as a list, each field edited on its own; arrays add and remove items.
  • For JSON, a line under the value says whether it is valid and where it isn't. Format indents it; Minify puts it on one line.

In code

The In code section under the details lists the lines of the project's scripts, in Assets and Packages, that name the selected key, grouped by script. Click a line to open it in your code editor.

A key counts as named when a script writes it out, or builds it: $"Level_{i}", string.Format("Level_{0}", i), "Level_" + i, a constant joined to a literal, or a settings class that joins a prefix to nameof(...). A key put together from variables alone isn't found. The scripts are read again when one changes.

The Sidebar

☰ Groups opens the sidebar; its edge drags to resize it.

  • All keys, Bookmarked and Hidden filter the list. Drop keys on Bookmarked to star them, or on Hidden to hide them.
  • Not in code lists PlayerPrefs keys no script names. They are candidates for keys an older version left behind; check before deleting.
  • Custom groups: ＋ New Group makes a group of keys picked by hand and keys that match its rules: starts with, ends with, contains, a wildcard (* and ?) or a regular expression, each optionally limited to one type, with Match all rules or any one. A group has a color, shown along the left edge of its keys' rows. Drop keys on a group to add them; right-click it to edit, duplicate or delete it, take a snapshot of its keys, or delete them.

Hide hides a key, or a whole prefix with keys added under it later; Hide Others hides everything but the selection. Bookmarks, groups and hidden keys are kept per project for PlayerPrefs, and per machine for EditorPrefs.

Watch

Watch reads the store again the moment anything writes it: editor scripts, other tools, another Unity. In Play Mode it also reads the PlayerPrefs on a timer, every 500 ms by default, saving the game's pending writes first so they show. Outside Play Mode, PlayerPrefs a script writes show once it calls PlayerPrefs.Save().

Changed Rows in Preferences chooses how a changed key shows:

  • Fade: a highlight that fades.
  • Mark Until Seen: the row stays marked until it is selected for a moment, with a button that puts back what it held. The bar under the list has Mark All Seen and Revert All.
  • Off: nothing.

The window's own edits only fade.

Snapshots

The Snapshots tab lists the store's snapshots on the left; the picked one is compared on the right with the current prefs or with another snapshot.

  • ＋ Take Snapshot saves every key. Take Snapshot of Selected in the toolbar's Snapshots ▾ menu saves only the selected keys: restoring it changes only those keys.
  • The Changed, Missing, Extra and Same chips show or hide each kind of difference, with their counts. Drag the lines between the column titles to resize the columns. Selecting a key shows both of its values in full below, JSON laid out and lined up with the differing lines tinted.
  • Each row's button puts that key back as the snapshot has it; select several and right-click to restore them together.
  • Restore Snapshot makes the current prefs match the snapshot, as one Undo step. A snapshot named Before restoring ... is taken first.
  • Double-click a snapshot to rename it. Its menu exports it as JSON or as sorted text, shows its file and deletes it.
  • Import reads a snapshot or a JSON export, such as one a teammate sent.

Play Mode

The Play Mode card on the Snapshots page has two switches:

  • Snapshot each session takes a snapshot as each Play Mode session starts, keeping the latest few. Snapshots you take yourself are never deleted.
  • Restore after Play (sandbox) puts the PlayerPrefs back as they were when Play Mode started, as it ends, so every run starts from the same state. One Undo step brings back what the game wrote. A Sandbox chip at the top of the window shows while it's on; clicking it turns the sandbox off.

Changes

The Changes tab records every change to the PlayerPrefs, in order, while Record is on. It records with the window closed, and Record stays on until you turn it off. A red Recording chip at the top of the window shows while it's on; clicking it stops recording.

  • Changes are grouped into Play sessions and Edit Mode stretches. Double-click a session to name it; Clear removes it.
  • Game, Editor and Anchor show or hide changes by who made them: the game in Play Mode, scripts and tools outside it, or this window.
  • ◆ Add Marker marks a moment with every key as it is. Restore to here puts the PlayerPrefs back as they were at the marker, and Snapshot saves them as a snapshot.
  • Group keys folds a key's changes in a session into one row; select it to see them all with a graph of a number key's values. By key lists each key once with how often it changed.
  • Clock time shows when each change happened by the clock, rather than the time into its session.
  • Each change can be reverted, shown on the Keys tab, or found in code. Export ▾ saves the log as JSON or CSV.

The log keeps the latest 5,000 changes, over script recompiles and Play Mode, until the Editor closes. EditorPrefs changes are recorded while Highlight EditorPrefs Changes is on in Preferences. The tab shows the changes of the store picked at the top of the window; the Changes page in its own window shows both stores.

The Snapshots and Changes pages each open in a window of their own from the button at their top right, to dock beside the keys or the Game view.

EditorPrefs

PlayerPrefs | EditorPrefs at the top left of the window picks the store every tab shows. EditorPrefs are Unity's: the Editor's and every package's settings, shared by every project and Unity version on the machine.

  • They are read-only until Allow editing is on, per window.
  • Unity writes EditorPrefs every few seconds, so their changes are followed quietly. Highlight EditorPrefs Changes in Preferences marks them as PlayerPrefs changes are.

Unity's Own Keys

Unity writes a few keys into every project's PlayerPrefs, for the player's window, resolution and quality.

  • Hide Unity Keys in Preferences, on by default, leaves them out of the list.
  • Shown, they are dimmed and read-only until Edit Unity Keys is on. A restore leaves them as they are.

Settings

The PlayerPrefs page under Preferences > Anchor has the module's switch and four sections:

  • List: Row Size (Compact, Comfortable, Large); Alternating Row Colors with its two colors, for the key list and the Snapshots comparison; Readable Names; Prefix Separators, the characters that split a key into parts for Show grouped and Readable Names, _./: by default; JSON Summaries; Row Buttons (Always, On Hover And Selection, or Never) and Row Buttons Shown, each button on its own.
  • Editing: List Edits, and Unity's own keys: Hide Unity Keys and Edit Unity Keys.
  • Watch: Watch for Changes with its Play Mode Interval (ms), Changed Rows with its Changed Row Color, and Highlight EditorPrefs Changes.
  • Play Mode: Snapshot on Play with Play Snapshots Kept, and Restore After Play (Sandbox).

With the module off, its menu item is disabled and Alt+S does nothing. Alt+S is registered with Unity's Shortcut Manager as Anchor > PlayerPrefs > Open Anchor PlayerPrefs, where it can be rebound or removed.

Compatibility

  • Windows only. Unity 2022.3 and Unity 6.
  • Editor-only. It adds nothing to a build, and a built player keeps its PlayerPrefs elsewhere.
  • Snapshots, bookmarks, groups and hidden keys of PlayerPrefs are kept in UserSettings/Anchor/PlayerPrefs/, in the project. GitHub's Unity .gitignore leaves UserSettings out of version control.
  • EditorPrefs' bookmarks, groups and hidden keys are kept in %LOCALAPPDATA%\AnchorStudios\PlayerPrefs\.
  • The window's settings are kept in the Editor's preferences on your machine.
